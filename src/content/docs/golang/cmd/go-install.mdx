## go install について

`go install` コマンドは、指定されたパッケージをコンパイルしてインストールします。

Go のプログラムは、コンパイルされたバイナリの実行形式が配布されている場合もありますが、ソースが公開されていて、それを go install コマンドでインストールできる場合もあります。Go 言語のコードの公開方法は多くの言語とは異なっています。
Java の Maven や Gradle、JavaScript の npm のように、パッケージをビルドしてインストールするようなツールはありません。(中央集権的なホストに依存する形になっていない)
代わりに、公開されているソースコードをダウンロードして、go install コマンドでインストールすることができます。

### syntax

```bash frame=none
go install [build flags] [packages]
```

`go install` コマンドに引数として、インストールしたいプロジェクトのソースコードリポジトリの場所を指定し、最後に `@` をつけてバージョンを指定します。

```bash frame=none
# 最新のバージョンの場合は @latest を指定します
go install github.com/user/project@v1.0.0
```

このコマンドを実行すると、`github.com/user/project` のソースコードのダウンロードをしてコンパイルを行いインストールされます。(`$GOPATH/bin` にインストールされます)

`go install` コマンドは、`go build` コマンドと同じようにビルドフラグを指定できます。

すでにインストールしてあるパッケージを更新する場合は、`@latest` を指定すればよい。

### 実行可能ファイルのインストール先

実行可能ファイルは `GOBIN` 環境変数で指定されたディレクトリにインストールされます。
`GOPATH` 環境変数が設定されていない場合、デフォルトで `$GOPATH/bin` または `$HOME/go/bin` にインストールされます。
$GOROOT 内の実行可能ファイルは、$GOBIN ではなく $GOROOT/bin または $GOTOOLDIR にインストールされます。

### モジュール対応モード

引数にバージョンサフィックス（@latest や @v1.0.0 など）がある場合、`go install` はモジュール対応モードでパッケージをビルドします。
この場合、カレントディレクトリやその親ディレクトリにある go.mod ファイルは無視されます。
これは、メインモジュールの依存関係に影響を与えることなく実行可能ファイルをインストールする際に便利です。

ビルドで使用されるモジュールのバージョンについてあいまいさを排除するため、引数は以下の制約を満たす必要があります:

- 引数はパッケージパスまたはパッケージパターン（"..."ワイルドカードを含む）である必要があります。
  標準パッケージ（fmt など）、メタパターン（std、cmd、all）、相対パスや絶対ファイルパスは指定できません。

- すべての引数は同じバージョンサフィックスを持つ必要があります。同じバージョンを参照する場合でも、異なるクエリは許可されません。

- すべての引数は、同じモジュール内の同じバージョンのパッケージを参照する必要があります。

- パッケージパスの引数は main パッケージを参照する必要があります。パターン引数は main パッケージのみにマッチします。

- どのモジュールもメインモジュールとは見なされません。コマンドラインで指定されたパッケージを含むモジュールに go.mod ファイルがある場合、そのファイルにはメインモジュールとして解釈された場合と異なる解釈を引き起こすようなディレクティブ（replace や exclude）を含んではいけません。また、モジュールは自身のより高いバージョンを要求してはいけません。

- どのモジュールでもベンダーディレクトリは使用されません。（'go install' でダウンロードされるモジュールの zip ファイルにはベンダーディレクトリは含まれていません。）

引数にバージョンサフィックスがない場合、`go install` は GO111MODULE 環境変数と go.mod ファイルの存在によってモジュール対応モードまたは GOPATH モードで実行されます。
詳細は `go help modules` を参照してください。
モジュール対応モードが有効な場合、`go install` はメインモジュールのコンテキストで実行されます。

モジュール対応モードが無効な場合、非メインパッケージは $GOPATH/pkg/$GOOS\_$GOARCH ディレクトリにインストールされます。
モジュール対応モードが有効な場合、非メインパッケージはビルドされ、キャッシュされますがインストールされません。

### 標準ライブラリのインストール

Go 1.20 より前では、標準ライブラリは $GOROOT/pkg/$GOOS*$GOARCH にインストールされていました。
Go 1.20以降では、標準ライブラリはビルドされキャッシュされますが、インストールはされません。
GODEBUG=installgoroot=all を設定することで、$GOROOT/pkg/$GOOS*$GOARCH の使用を元に戻すことができます。

ビルドフラグについては `go help build` を参照してください。

パッケージの指定方法については `go help packages` を参照してください。

パッケージの指定方法の詳細については `go help packages` を参照してください。

`go build`、`go get`、`go clean` も参照してください。
