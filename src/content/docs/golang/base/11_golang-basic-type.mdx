## 基本型(primitive type)

### ゼロ値

宣言されたが、値が割り当てられていない変数に対しては、デフォルトのゼロ値(zero value)が設定される。
比較的新しい言語においては、ゼロ値はデフォルト値としてよく使われます。
明示的なゼロ値があることでコードがクリアになり、C や C++ でありがちなバグを防ぐことができます。

#### それぞれの型のゼロ値

```go
package main

import (
	"fmt"
)

func main() {
	{
		var i int
		var f float64
		var b bool
		var s string

		fmt.Println("i:", i)
		fmt.Println("f:", f)
		fmt.Println("b:", b)
		fmt.Printf("s:|%s|\n", s)
	}
}
```

```bash frame=none
go run zero.go

# i: 0
# f: 0
# b: false
# s:||

```

### リテラル

Go 言語におけるリテラルとは、数値、文字、文字列などの固定値をソースコード内に直接記述するものです。主なリテラルの種類には、整数リテラル、浮動小数点リテラル、文字リテラル、文字列リテラルの 4 つがあり、さらに複素数リテラルも存在します。これらのリテラルを使用することで、プログラマは定数値を簡潔かつ明確にコード内で表現することができます。

#### 整数リテラル

整数リテラルは数字の並びで表現されます。通常は 10 進数で表現されますが、2 進数、8 進数、16 進数でも表現できます。

```go
// 10 進数
123
// 2 進数(0b で始まる...binary)
0b1010
// 8 進数(0o で始まる...octal)
0o123
// 16 進数(0x で始まる...hexadecimal)
0x1A
```

また、Go 言語では、長い数字の文字を読みやすくするために、`_` を使用して桁を区切ることができます。

```go
123_456_789
```

ただし、先頭と末尾には使用できませんし、連続して使用することもできません。

```go
// 先頭に使用できない
_123
// 末尾に使用できない
123_
// 連続して使用できない
123__123_123
```

10 進数では 3 文字ごとで区切るのに対して、2 進数、8 進数、16 進数では 2 文字または 4 文字ごとで区切るのが一般的です。

```go
123_456_789
0b1010_1010
0o123_456
0x1A_BC_DE
```

#### 浮動小数点リテラル

浮動小数点リテラルは、整数部と小数部をドット(.)で区切って表現されます。
また、指数表記も可能です。

```go
123.456
1.23456e+2
1.23456e-2
```

0x を前につけると、16 進数の浮動小数点リテラルとして扱われます。

```go
0x1.23456p+2
0x1.23456p-2

// _ を使用して桁を区切ることができる
123.456_789
```

### rune リテラル

rune リテラルは、文字列リテラルと同じように、`'` で囲んで表現されます。(例えば、'a'や'あ'などが該当)
rune リテラルは、Go 言語において単一の Unicode コードポイントを表すデータ型です。
実際には `int32` 型のエイリアスです。rune を使用することで、幅広い文字や特殊文字を扱うことが可能です。
これにより、ASCII 文字だけでなく、様々な言語や絵文字などの複雑な文字を扱うことができます。

:::note[rune の語源]

**「rune」の語源と一般的な意味:**

- 古代ゲルマン語族で使用されていた文字体系「ルーン文字」に由来します
- 主に紀元 3 世紀から中世にかけて、北欧やゲルマン民族によって使用されました
- 「秘密」や「神秘的な文字」という意味合いも持っています

**Go 言語における rune:**

技術的定義:

- rune は int32 のエイリアス（別名）として実装されています
- Unicode のコードポイントを表現するために使用されます
- 1 つの文字（Unicode 文字）を表現する型です

このように、古代の文字体系の名前を借りて、現代のプログラミング言語で文字を扱うための型として採用されているのが興味深い点です。Go 言語では、国際化対応を念頭に置いて設計されており、rune 型の採用はその一例と言えます。

:::

#### rune の使用例

```go
package main

import "fmt"

func main() {
    var r rune = 'あ'
    fmt.Printf("Character: %c, Unicode: %U\n", r, r)
}
```

このプログラムでは、`rune`型の変数 `r` に日本語の文字 `'あ'` を割り当て、`fmt.Printf` を使ってその文字と Unicode コードポイントを出力しています。

```go
// 文字列から rune のスライスを作成
str := "Hello, 世界"
runes := []rune(str)

// rune として文字を定義
r := 'A'  // rune型の変数
```

##### 特殊文字のエスケープ

```go
// エスケープシーケンス
'\n' // 改行
'\t' // タブ
'\r' // 復帰
'\b' // バックスペース
'\'' // シングルクォート
'\"' // ダブルクォート
'\' // バックスラッシュ
```

#### 特徴

- UTF-8 でエンコードされた文字列を扱う際に特に有用です
- マルチバイト文字（日本語や絵文字など）を適切に処理できます
- 1 文字が必ず 1 つの rune として扱われるため、文字単位の処理が容易です

##### byte との違い

`byte` は `uint8`型のエイリアスで、主に ASCII 文字などの単一バイトの文字を扱います。一方、`rune` は 32 ビット幅を持ち、より多くの文字を表現することが可能です。

[文字列 rune byte の変換](/golang/base/12_golang-composite-type/#文字列-rune-byte-の変換)

```go
'a'
'あ'
```

##### 数字を扱う

rune リテラルについては、コードがわかりやすくなるという場合を除いて 16 進表記は避け、数値リテラルを表すには 10 進表記を用いるのがよい。8 進数表現は、POSIX のパーミッションフラグの値を表すのに用いられますが、(例えば 0o777 で rwxrwxrwx を表す)、その他のケースではめったに使われません。16 進数や 2 進数の表現は、ビットフィルタやネットワークアプリケーションなどで使われる場合があります。

### 文字列リテラル

文字列リテラルは、ダブルクォーテーションで囲んで表現されます。

#### 解釈済み文字列リテラル (interpreted string literal)

0 個以上の rune リテラルを含むことができます。
ここで使えない文字としてはエスケープシーケンスがあります。(例えば、`\n` や `\t` など)また、ダブルクォーテーション自体もエスケープシーケンスとして扱われます。

```go
// 解釈済み文字列リテラル
"Hello, World!"

// \n で改行
"Hello,\nWorld!"

// 生文字列リテラル
`Hello, World!`
```

#### 生文字列リテラル (raw string literal)

文字列中に 「\」、改行、あるいは 「"」を含めたい場合は 「\`」(バッククォート)で囲まれた生文字列リテラルを使用します。
「\`」以外の任意の文字を含めることができます。

```go
// 改行を含める
fmt.Println(`Hello,\nWorld!`)

// fmt.Println arg list ends with redundant newline
fmt.Println(`Hello,
  World!
    Goodbye!
      Farewell!
`)

// 「"」を含める
fmt.Println(`このようにダブルクォートで囲んだ "Hello, World!" も使うことができます。`)
```

:::note[UTF-8]

言語仕様によれば、Go のソースコードは常に UTF-8 で書かれます。
したがって、16 進数のエスケープを使わない限り、文字列リテラルは UTF-8 で書かれます。
:::

#### 複素数リテラル

#### リテラルと型

サイズが異なる整数については加算さえもできません。一方、整数リテラルを浮動小数点の式で使ったり、整数リテラルを浮動小数点型の変数に代入することは可能です。
これは、**Go 言語においてはリテラルは「型がない(untyped)」** ためで、リテラルと互換性を持つ任意の変数に代入できるということです。

ただし、

- 文字列リテラルを数値型の変数に代入できません
- 数値リテラルを文字列の変数に代入することもできません
- 浮動小数点数型のリテラルを整数型の変数に代入することもできません

```go
// エラーになる例
var i int = "Hello, World!" // 文字列リテラルを数値型の変数に代入
var s string = 123 // 数値リテラルを文字列の変数に代入
var f float64 = 123 // 浮動小数点数型のリテラルを整数型の変数に代入

// エラーにならない例
var i int = 123 // 数値リテラルを数値型の変数に代入
var s string = "Hello, World!" // 文字列リテラルを文字列の変数に代入
var f float64 = 123.456 // 浮動小数点数型のリテラルを浮動小数点数型の変数に代入
```

リテラルが型を持たないのは Go が実践的なプログラミング言語であることを反映しています。
プログラマーが指定するまで型を避けるほうがプログラミングしやすいでしょう。

ただし、サイズの制限があります。整数として保存できるのは 2^64 までです。
最大値を超える数値リテラルを書くことはできるが、指定された変数を溢れさせてしまうリテラルを代入しようとするとコンパイルエラーになります。
たとえば、1000 を byte 型の変数に代入しようとするとエラーになります。

```go
var b byte = 1000 // コンパイルエラー
```

型が明示的に指定されない変数はデフォルトの型が設定されます。

### 論理型 bool

真偽値 (論理型、ブール値) を値としてもつ変数の型は論理型になります。
論理型の変数は true、または false のいずれかの値をとります。論理型は 1 バイトのサイズを持ちます。

ゼロ値: false

```go
var flag bool // デフォルト値は false

flag := true
```

### 数値型

Go 言語には合計 12 種類の数値型があります。これらは 3 つのカテゴリに分類されます。

#### 整数型

Go 言語で整数を表す型には、符号付き整数と符号なし整数の 2 種類があり 1 ~ 4 バイトのサイズを持ちます。

ゼロ値: 0

uint 型は符号がないため、負の数を表現できません。

int 型で違う型同士での演算ができません

```go
var a int = 1

```

そのため、変数の型がわからなくなってしまった場合、
型を確認して型変換を行い演算をできるようにしてみます。

```go
var a int = 1
var b uint8 = 2

// %T で型を表示してくれる
fmt.Printf("%T\n", b) // unit8
fmt.Printf("%T\n", int(b)) // int

fmt.Println(a + int(b)) // 3
```

##### 整数型の選択

整数型を表現する型がいくつもありますので、どれを選択するかについては、以下の点を考慮して選択するとよいでしょう。

- 特定の大きさと特定の符号の整数バイナリのファイルあるいはネットワークプロトコルを処理しているのであれば対応する整数型を使う

  例: ネットワークプロトコルでは 16 ビットの符号付き整数を使っている

  ```go
  var a int16 = 123
  ```

- すべての整数型について機能するライブラリ関数を書く場合は 2 つの関数を書く。一つは引数と戻り値が int64 のもの、もう一つが uint64 のもの。

- そのほかの場合は int 型を使う

##### 整数関連の演算子

```go
// 加算
a + b
// 減算
a - b
// 乗算
a * b
// 除算
a / b
// 剰余
a % b
```

除算で浮動小数点型の結果を得たい場合は float64 型または float32 型の変数に代入する

```go
var f float64 = 3 / 2
// f は 1.5 になる

var x int = 3 / 2
// x は 1 になる
```

0 による除算をしてしまうと、パニック(メッセージとスタックトレースを出力してプログラムを終了する)になるので避けましょう。

```go
var x int = 3 / 0
```

```bash frame=none
panic: runtime error: integer divide by zero
```

変数に対して演算を行なって、その結果を変数に代入する場合は

```go
var x int = 3

x += 1 // x は 4 になる
x -= 1 // x は 3 になる
x *= 1 // x は 3 になる
x /= 1 // x は 3 になる

// 整数の比較には == 、!= 、< 、<= 、> 、>= を使う
y := 1

x == y // true
x != y // false
x < y // false
x <= y // false
x > y // true
x >= y // true

// 論理演算子
x && y // true
x || y // true
!x // false

```

##### [ビット演算](/golang/base/30_mathmatic/#ビット演算)

```go
// ビット演算子
x & y // 論理積(AND)
x | y // 論理和(OR)
x ^ y // 排他的論理和(XOR)
x &^ y // 論理積(AND NOT)
x << y // 左シフト
x >> y // 右シフト

// ビット演算子の例
var a uint8 = 0b1010
var b uint8 = 0b1100

a | b // 0b1110
a ^ b // 0b0110
a << 1 // 0b10100
a >> 1 // 0b0101
```

#### 浮動小数点数型

Go 言語の浮動小数点数型は、IEEE 754 標準に準拠しています。float32 と float64 の 2 種類があります。

ゼロ値: 0

<Table
  columns={["型", "サイズ", "範囲(最小値 ~ 最大値)"]}
  data={[
    ["float32", "4 バイト", "-3.402823e+38 ~ 3.402823e+38"],
    ["float64", "8 バイト", "-1.7976931348623157e+308 ~ 1.7976931348623157e+308"],
  ]}
/>

```go
var f float64 = 123.456
fmt.Println(f) // 123.456

f2 := 789.1011
fmt.Println(f2) // 789.1011

fmt.Printf("%T, %T\n", f, f2) // float64, float64

fmt.Println(f + f2) // 912.5571

var fl32 float32 = 789.1011
fmt.Printf("%T\n", fl32) // float32

//fmt.Println(f + fl32) // invalid operation: f + fl32 (mismatched types float64 and float32)

// 型変換を行うことで演算ができるようになる
fmt.Println(f + float64(fl32)) // 912.55707421875
```

浮動小数点数リテラルのデフォルトの型も float64 です。特になにも考慮事項がない場合は float64 を使うのがよいでしょう。
float32 は 10 進数で 6 ~ 7 桁の精度を持ち、float64 は 15 ~ 16 桁の精度を持ちます。

グラフィックスや物理演算などに限定した用途で利用するのがいい型です。

:::caution

浮動小数点数は 10 進数を正確に表現できません。金額など誤差なしで 10 進数を表現しなければならない場合は使わないでください。

:::

浮動小数点数については四則演算子、比較演算子、論理演算子を使うことができます。
非ゼロの浮動小数点数を 0 で除算すると +Inf または -Inf (少数の符号によって、正の無限大または負の無限大) になります。

0 が記憶された浮動小数点数型の変数を 0 で除算すると NaN (Not a Number) になります。

```go
// 非ゼロの浮動小数点数を 0 で除算すると +Inf または -Inf になる
var x float64 = 1

x / 0 // +Inf

// 0 が記憶された浮動小数点数型の変数を 0 で除算すると NaN になる
var y float64 = 0

y / 0 // NaN
```

#### 複素数型

Go 言語には複素数もサポートしています。複素数型は complex64 と complex128 の 2 種類があります。

<Table
  columns={["型", "サイズ", "範囲", "実部と虚部の型"]}
  data={[
    ["complex64", "8 バイト", "-2^63 ~ 2^63-1", "float32"],
    ["complex128", "16 バイト", "-2^127 ~ 2^127-1", "float64"],
  ]}
/>

どちらも組み込みの関数 `complex` を使って作成できます。

```go
var x complex64 = complex(1, 2)
var y complex128 = complex(3, 4)

// 実部を取得
real(x) // 1
// 虚部を取得
imag(x) // 2

// 複素数の加算
x + y

// 複素数の減算
x - y

// 複素数の乗算
x * y

// 複素数の除算
x / y
```

- 関数の引数に型のない(untyped)の定数やリテラルを渡すと、型のない複素数リテラルを生成します。このときのデフォルトの方は complex128 になります。
- complex に渡された値がいずれも float32 の場合は complex64 になります。
- 一つの値が float32 で、もう一つの値が型のない定数あるいはリテラルの場合で、float32 におさまる場合は complex64 になります。
- これ以外の場合は、complex128 になります。

複素数の計算も標準の整数型、浮動小数点数型と同じように行うことができます。

複素数の比較も標準の整数型、浮動小数点数型と同じように行うことができますが、精度の問題で正確な比較ができないことがあります。
複素数の実部と虚部をそれぞれ比較することで正確な比較ができます。

```go
// 二つの複素数の比較
x == y
x != y

// 複素数の実部と虚部をそれぞれ比較
real(x) == real(y) && imag(x) == imag(y)
```

パッケージ math/cmplx には複素数の計算を行う関数があります。

```go
// 複素数の計算
cmplx.Abs(x)
cmplx.Pow(x, y)
cmplx.Sqrt(x)
```

<LinkPreview url="https://github.com/mushahiroyuki/lgo/blob/main/example/ch02/ex0201.go" type="inline" />

```go
package main
import (
	"fmt"
	"math/cmplx"
)

func main() { //liststart
	x := complex(2.5, 3.1)
	y := complex(10.2, 2)
	fmt.Println(x + y) // (12.7+5.1i)
	fmt.Println(x - y) // (-7.699999999999999+1.1i)
	fmt.Println(x * y) // (19.3+36.62i)
	fmt.Println(x / y) // (0.2934098482043688+0.24639022584228065i)
	fmt.Println(real(x)) // 2.5
	fmt.Println(imag(x)) // 3.1
	fmt.Println(cmplx.Abs(x)) // 3.982461550347975
}//listend
```

`fmt.Println(x - y) // (-7.699999999999999+1.1i)` などの結果を見ると浮動小数点数型の精度の関係で結果がキリの良い数値になっていないことがわかります。
なお、基本型のリテラルとして複素数の虚部のみからなるリテラルがサポートされています。浮動小数点数リテラルと似ていますが、最後に `i` をつきます。

複素数が組み込み型としてサポートされていますが、数値計算に Go 言語が使われることはありません。
行列のサポートがないこと、ライブラリがあまり充実していないことなどによりスライスのスライスを使ったりしなければならないことなどの制約があるためです。
しかし、大規模なプログラムの一部でマンデルブロ集合を計算する必要がある場合は、二次方程式の解を求めるために複素数型を使うことがあります。
なぜ、Go 言語で複素数がサポートされているのかは、Go (および Unix) の中心的開発者のひとりである Ken Thompson が、そのほうがよいと思ったからです。将来のバージョンから、複素数のサポートを取り除こうという議論もありますが、不要なら使わなければ良いだけのことです。

:::tip[Gonum]

数値計算のアプリケーションを Go で記述したいのならば、サードパーティのパッケージである Gonum が利用できます。
線形代数、行列、積分、統計などでのライブラリがあり、複素数を扱うことができます。
もっとも、まずはほかの言語を使うことを検討した方が良いかもしれません。

<LinkPreview url="https://www.gonum.org/" />

:::

### 文字列型と rune 型

Go の文字列も基本型(組み込み型)です。

ゼロ値: 空文字列

```go
var s string
```

Go は Unicode をサポートしているため、文字列に Unicode 文字を含めることができます。
整数、浮動小数点数と同様に、文字列の比較にも `==` 、`!=` を使うことができます。
順序の比較にも `<` 、`<=` 、`>` 、`>=` を使うことができます。
文字列の連結にも、`+` を使うことができます。

```go
// 文字列の比較
s == t
s != t

// 文字列の順序の比較
s < t
s <= t
s > t
s >= t

// 文字列の連結
s + t
```

Go の文字列はイミュータブル(変更不可能)です。
したがって、文字列型の変数に現在記憶されているものとは別の値を代入することはできますが、代入された後の文字列の値を変更することはできません。

```go
// 文字列の変更
s = "Hello, World!"
s[0] = 'H' // エラー
```

文字列の変更には、`strings` パッケージの `Replace` 関数を使うことができます。

```go
// 文字列の変更
s = "Hello, World!"
s = strings.Replace(s, "Hello", "Hi", 1)
```

コードポイント(rune)は、文字列の中の一文字を表す型です。rune は int32 の別名です。

```go
// コードポイント(rune)
var r rune = 'A'
```

rune リテラルのデフォルトの型は rune 型です。文字列リテラルのデフォルトの型は文字列(string)型です。

### 明示的型変換

数値の型を複数持つ言語では「暗黙な型変換」が行われることがあります。
それは、便利な反面、型変換を正しく行うためのルールが複雑になるという欠点があります。
そのため、予期しない結果になる場合があります。
Go 言語では明快さと可読性に重きを置いており、変数間の暗黙な型変換は行われません。
そのため、明示的な型変換が必要です。
型が違う場合は、型変換が必要です。

```go
// 明示的な型変換
var x int = 1
var y float64 = float64(x)
```

<LinkPreview url="https://github.com/mushahiroyuki/lgo/blob/main/example/ch02/ex0202.go" />

```go
package main
import (
	"fmt"
)

func main() {
	var x int = 10 //liststart
	var y float64 = 30.2
	var z float64 = float64(x) + y
	var d int = x + int(y)
	fmt.Println(z, d) // 40.2 40   //listend
}
```

## 変数宣言

Go はさまざまな変数宣言の方法があります。

### 変数宣言と再代入、省略記法も

```go
// 最も詳細な指定の宣言方法
var 変数名 型 = 値

// ex.
var x int = 10
```

整数リテラルのデフォルトの型は int であるため、型指定を省略できる。

```go
// 型指定を省略した宣言方法
var 変数名 = 値

// ex.
var x = 10

// 再代入
変数名 = 値
// ex.
x = 20
```

また、変数に値を代入しない宣言の場合はその型のゼロ値が代入される。

```go
// ゼロ値の代入
var x int
```

:::caution[number declared and not used]
Go では、定義したものの使用していない変数がある場合、エラーとなる。

```go
// エラー
var number int
```

例. `./main.go:25:6: number declared and not used`  
number という変数が定義されているが、利用されていない

Go のひとつのゴールとして「大規模なチームによる共同開発を容易にする」というものがあります。
また、もうひとつに「宣言された局所変数(ローカル変数)はすべて使わなければならない」というルールがあります。
宣言されたにも関わらず、一度もその値が参照されない場合は、コンパイルエラーを引き起こします。

これを回避する方法としては、変数に値が代入されたがその値は使われなかった状態を作るということです。

```go
// エラー
var number int
// このように、コンパイルエラーとなります。

// 回避方法(変数に値が代入されたがその値は使われなかった)
var _ int = 10
```

定数は未使用であっても大丈夫です。

:::

多重代入は同じ型の複数の値を同時に代入できます。

```go
// 多重代入
var x, y int = 10, 20

// 初期値を指定しない多重代入
var x, y int

// リテラルの多重代入(型推論)
var x, y = 10, "Hello"
```

さらに、複数の宣言をまとめた宣言リストもあります。

```go
// 宣言リスト
var (
  x int = 10
  y string = "Hello"
  z float64 = 3.14
  d, e int = 10, 20
  f, g = true, "World"
  h string
)
```

#### 省略記法

var を省略した宣言方法です。演算子 `:=` を使うことで、型推論が行われます。

```go
// 省略記法
変数名 := 値

// ex.
x := 10
y, z := 20, "Hello"
```

この省略記法は、再代入の時にはこのように使うことが明示的です。
`:=` は、制限があり、パッケージレベルで変数を宣言する場合は、var を使わなければなりません。`:=` は関数レベルでのみ使うことができます。
つまり、関数内で最もよく使われるのは `:=` です。パッケージレベルの複数の変数を宣言するのならば、宣言リストを使います。

:::caution[`:=` を避けるべき時]

- 変数をゼロ値に初期化する場合は `var x int` の形式にしましょう。ゼロ値が意図されていることが明確です。
- 型が指定されていないリテラルを変数に代入する時、`var x = 10` の形式にしましょう。型推論が行われるため、コードが読みやすくなります。

:::

var や := を使うと複数の変数の宣言を 1 行で行えますが、このスタイルを使うのは、複数の値を返す関数(あるいは「カンマ ok イディアム」)からの戻り値を代入する時だけにしましょう。

```go
// 複数の変数の宣言
var x, y int = 10, 20

// 複数の値を返す関数からの戻り値を代入
x, y := f()
```

関数の外で変数の宣言をする必要はほとんどありません。基本的にパッケージレベルの変数の値を変更するのは避けましょう。
関数の外にある変数は値の追跡が困難で、その結果プログラム中のデータフローの理解が妨げられることになり、バグにつながります。
一般的にパッケージブロックにおいては基本的にはイミュータブル(変更不可)な変数のみを宣言するべきとなります。

## 定数

多くの言語のイミュータブル(変更不可)なものを宣言する方法に定数というものがあります。
Go ではそのために `const` を使います。ほかの言語と同様に動作するかのように見えますが、違いがあります。

<LinkPreview url="https://github.com/mushahiroyuki/lgo/blob/main/example/ch02/ex0203.go" />

```go
package main

import "fmt"

const x int64 = 10

const (
	idKey   = "id"
	nameKey = "name"
)

const z = 20 * 10

func main() {
	const y = "hello"

	fmt.Println(x)
	fmt.Println(y)

	x = x + 1
	y = "bye"

	fmt.Println(x)
	fmt.Println(y)
}
```

こちらを実行すると、エラーとなります。

```
./prog.go:20:2: cannot assign to x (neither addressable nor a map index expression)
./prog.go:21:2: cannot assign to y (neither addressable nor a map index expression)

Go build failed.
```

定数を宣言するのはパッケージレベルあるいは関数内です。
var と同様に、`()` で囲んで、関連する複数の定数を宣言することもできます。(変数と違いまとめて書く方が効率的)
Go の const はリテラルに名前をつけるためのものです。コンパイル時に決定できる値を保持できるだけなのです。

つまり、代入できるのは

- 数値リテラル
- 文字列
- true および false
- rune
- complex, real, imag, len, cap, unsafe.Sizeof などの組み込み関数
- 上で挙げた値と演算子から構成される式

## 型つきの定数と型のない定数

定数には型があるものと、ないものがあります。型がないというのは、リテラルと同様です。
型のない定数はデフォルトの型を持ち、同じ型の変数に代入することもできます。

```go
const x int = 10

// 型のない定数はデフォルトの型を持ち、同じ型の変数に代入することもできます。
var y int = x
```

## 変数および定数の名前

Go の変数定数の名前は、キャメルケースを使います。
また、変数の名前は「文字」あるいは `_` で始まり、その後に「文字」「数字」「\_」が続きます。

```go
// 変数の名前
var x int
var _ int = 10
var x1 int = 10
```

定数の名前は、キャメルケースを使います。Go 以外の言語ではパスカルケースを利用することがほとんどです。
パッケージレベルの宣言において、名前の先頭文字が大文字か小文字(アッパーキャメルかローカルキャメル)かで、その変数がパブリックかプライベートかが決定されます。

```go
// パッケージレベルの宣言
var X int = 10
var x int = 10
```
