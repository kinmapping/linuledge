## ポインタ

ポインタは、メモリアドレスを指す変数です。ポインタを正しく使うことで、Go プログラムがより高速に効率よく動作させることができます。

### ポインタの入門

ポインタとは、ある値が保存されているメモリ内の位置を表す変数です。
次のコードにより変数がメモリに保存される様子を示しました。

```go
var x int32 = 10
var y bool = true
```

これを図にすると次のようになります。

どの変数も、1 バイトもしくは何バイトか連続したメモリに保存されており、その位置のことをアドレスといいます。
変数の型が違えば、保存時に必要なメモリの量も異なります。
上記の例では、`int32` 型の変数 `x` は 4 バイト分のメモリを占有しています。
`bool` 型の変数 `y` は 1 バイト分のメモリを占有しています。

このように、変数の型によって必要なメモリの量が異なるため、変数の型によってアドレスの位置も異なります。
4 バイトを占有するということは 1 〜 4 のアドレスに保存され、y の 1 バイトは 5 のアドレスに保存されています。
ポインタは、通常の変数と同じ「箱」ですが、その中に入っている「値」が数値や文字列などではなく、別の変数（別の箱）が置かれている場所（メモリ上のアドレス）そのものを示しています。

:::tip[通常の変数とポインタの違い]

**通常の変数**

変数 A に数値 10 が入っているなら、A は「10」という直接の値を持っています。

**ポインタ変数**

一方、ポインタ変数 B は、「A がどこにあるか」という情報、つまり A のメモリアドレス（例：0x7ffeeb3ff618 など）を持っています。
このため、B に「アクセスする」と、A の値 (10) にたどり着くことができるのです。
この仕組みにより、プログラムはアドレスを介して間接的にデータにアクセスでき、効率的なメモリ管理やデータの共有が可能になります。

:::

```go
var x int32 = 10
var y bool = true

pointerX := &x
pointerY := &y

var pointerZ *string
```

変数の型が違うと、保存に利用するメモリはその方に応じた容量になりますが、ポインタは常に同じサイズになります。
変数の容量ではなく、メモリ内での格納位置を示すためのメモリの量になるということです。
x へのポインタである `pointerX` はアドレス 6 に保存され、値は `0001` となっていますが、これが x のメモリアドレスを示しています。
となると、`pointerY` は `0005` となり、y のメモリアドレスを示しています。
`pointerZ` は `0000` となり、まだ値がなにも参照していないことを示しています。

## ポインタの宣言

Go のポインタの構文は C や C++ から一部借用していますが、Go にはガベージコレクタがあるため、メモリ管理ははるかに簡単です。ポインタに関する演算、C や C++ で可能なポインタの操作はできません。

### アドレス演算子とでリファレンス

`&` はアドレス演算子です。変数の前につけるとその変数のアドレスを返します。
返された値はポインタ型の値になります。

```go
x := 10
pointerX := &x
// ポインタ型の値を確認
fmt.Println(pointerX) // 0xc000012070
```

参照しているアドレス情報をもとに、格納されている値を見るには `*` を変数名の前につけて宣言します。
`*ポインタ変数` として出力結果を確認する

```go
fmt.Println(*pointerX) // 10
```

このようにして、変数の参照アドレスや、ポインタが参照するデータを取得して確認します。

nil ポインタ (アドレス 0) のデリファレンスを試みると、実行時エラーが発生します。そのため、d エリファレウンス

### ポインタのデフォルト値

ポインタのデフォルト値は `nil` です。
